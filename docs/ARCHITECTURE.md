# Архитектура

Клиентское приложение «Петербург в деталях» — Flutter-приложение для Android,
которое соединяет официальный Yandex MapKit с внешним FastAPI backend.
Серверная часть в этот репозиторий не входит; здесь описаны только её
контракты, которые использует клиент.

## Слои

```
Экраны и виджеты (lib/ui)
        │
        ▼
Состояние приложения (lib/providers, Provider)
        │
        ├──► Каталог и поиск ──► lib/data/repositories ──► dio ──► FastAPI backend
        ├──► Карта и маршрут ──► lib/services/mapkit_service ──► Yandex MapKit Full SDK
        ├──► Экологические оценки (shade, quiet, puddle, pollen) ──► FastAPI backend
        ├──► ИИ-помощник ──► FastAPI backend ──► OpenRouter (SSE)
        └──► Голос ──► системный распознаватель Android + системный TTS
                          │
                          ▼
                Локальное хранение: shared_preferences
```

Редакционные наборы (каталог городских впечатлений, scenic-объекты OSM,
подборки «Открой город») лежат в `lib/data` и не требуют сети.

## Каталог и backend

Каталог мест отдаёт backend (`GET /places`, `GET /places/categories`,
`GET /places/{id}`) с фильтрами по категориям, поиском и пагинацией. Карточка
места открывается отдельным запросом. Исторические справки
(`GET /places/{id}/history`) обслуживаются из редакционного набора на сервере,
без обращения клиента к сторонним сайтам.

Географические факты каталога происходят из OpenStreetMap и распространяются
под ODbL 1.0. Машиночитаемый каталог вместе с доказательной базой лежит в
[`data/`](../data/README.md).

Ошибки сети и контракта показываются пользователю: встроенной офлайн-базы и
автоматической подмены данных нет. Поздний ответ предыдущего запроса не
заменяет результаты новых фильтров.

## Карта и пешеходный маршрут

Карта — нативный `MapWindow` официального пакета `yandex_maps_mapkit` 4.45.0.
Проект добавляет только условные маркеры мест и старта и геометрию маршрута,
полученную от SDK; линии улиц и рек не рисуются.

Пешеходный маршрут строится `TransportFactory.instance.createPedestrianRouter()`
для двух точек. Расстояние, время и геометрия копируются из ответа SDK
(`MasstransitWeight`, `MasstransitRoute.geometry`); инструкции манёвров
формируются из данных SDK, а не придумываются. Backend геометрию пешеходного
маршрута не рассчитывает.

```
UI → RoutingProvider → MapKitService → PedestrianRouter → сервис Яндекса
```

Устаревшие ответы отбрасываются, предыдущий запрос отменяется, у запроса есть
таймаут. Точка старта выбирается явно: «Моё местоположение», место из каталога,
точка на карте или результат внешнего поиска.

## Живая навигация

Сопровождение по маршруту считывает GPS через `geolocator`, сопоставляет
позицию с текущим участком и показывает инструкцию манёвра. Ключевые
ограничения осознанны:

- **Ручное перестроение.** Отклонение от маршрута обнаруживается и
  показывается, но новый маршрут строится только по действию пользователя.
  Автоматического перестроения нет.
- **Ручное прибытие.** Подтверждение «Я на месте» требует актуального GPS,
  остатка участка не более 150 м и расстояния до его конца не более 150 м.
  Потерянный сигнал и устаревший прогресс прибытие не подтверждают.
- **Без фонового сервиса.** Приложение не отслеживает геолокацию в фоне и не
  хранит историю перемещений.

## Smart Walk и Scenic

Smart Walk — редакционный планировщик: пользователь выбирает типы мест, бюджет
времени и мягкий приоритет необычных объектов, после чего backend
(`POST /routes/propose-walk`) предлагает последовательность из каталога.
Итоговый маршрут всё равно строится MapKit, а бюджет сверяется как «пешком по
MapKit + редакторский осмотр». Это не ИИ-планирование.

Scenic-приоритет использует локальный набор проверенных пешеходных
пространств (набережные, пешеходные улицы, площади) из
`lib/data/scenic/scenic_dataset.dart`. Набор построен из OSM-данных
(ODbL 1.0), а точки привязаны к подтверждённым публичным пешеходным путям, а
не к центрам парков. Происхождение и скрипты повторной сборки —
`data/provenance/phase_c5/`.

## Экологические оценки

Shade, Quiet, Puddle и Pollen считает backend по открытым данным, а клиент
только отправляет геометрию существующей прогулки и отображает результат:

| Оценка | Endpoint | Природа результата |
| --- | --- | --- |
| Shade | `POST /environment/shade/analyze` | Модель затенённости зданиями на заданное время |
| Quiet | `POST /environment/quiet/analyze` | Относительный прокси шумовой нагрузки, без децибел |
| Puddle | `POST /environment/puddle/analyze` | Относительная склонность поверхности к лужам |
| Pollen | `POST /environment/pollen/analyze` | Смоделированные концентрации по видам, без «уровней опасности» |

Клиент проверяет контракт вместо доверия к нему: незнакомая единица
концентрации, отсутствие участков или нарушенная структура ответа приводят к
явному отказу, а не к подстановке придуманного значения. Запрос, чья геометрия
не входит в лимит тела запроса, отклоняется до отправки — усечённая геометрия
дала бы выдуманную оценку.

## ИИ-помощник

Ассистент отправляет на backend текст вопроса, историю диалога и (при наличии)
идентификатор места в каталоге; ключ OpenRouter и выбор модели остаются на
сервере. Ответ приходит потоком SSE и разбирается на клиенте. Перед первым
вопросом требуется отдельное согласие; после отзыва новые вопросы не
отправляются. Карта, поиск и навигация работают без ассистента.

## Голос

Распознавание выполняет системный распознаватель Android через собственный
Kotlin-мост: приложение не получает, не сохраняет и не передаёт аудиозапись
само. Поскольку выбранный в системе распознаватель может обрабатывать речь по
сети, включение требует явного согласия пользователя. Озвучивание инструкций
выполняет системный Android TTS; приложение хранит только локальные настройки
голоса.

## Локальное хранение

| Ключ | Содержимое |
| --- | --- |
| `smartnavigator.guest` | Избранное и гостевые предпочтения |
| `smartnavigator.theme_mode` | Светлая/тёмная тема |
| `smartnavigator.voice` | Настройки озвучивания |
| `smartnavigator.voice_search` | Согласие на системное распознавание речи |
| `smartnavigator.ai_consent` | Версия принятого согласия ИИ |

Аккаунтов, серверных сессий и синхронизации пользовательских данных между
устройствами нет. Подробнее: [PRIVACY.md](PRIVACY.md).

## Конфигурация клиента

Конфигурация (`MAPKIT_API_KEY`, `API_BASE_URL`, `APP_ENV`) загружается и
проверяется до инициализации MapKit и до создания сетевых репозиториев. Ошибка
называет настройку и способ исправления, но не выводит значение ключа.
Правила, приоритет и примеры: [CONFIGURATION.md](CONFIGURATION.md).

## Границы проверки

Автотесты проверяют модели, сериализацию запросов, обработку ошибок,
провайдеры, экраны, доступность и брендинговые ресурсы. Компиляция Android
проверяет Dart-код, ресурсы и нативные зависимости.

Реальная карта, настоящий пешеходный маршрут, GPS на устройстве,
системное распознавание речи, озвучивание и авторизация ключа MapKit
проверяются только на физическом устройстве с действующим ключом; успешная
сборка этого не подтверждает. Статус таких проверок фиксируется отдельно, а не
выводится из зелёного набора тестов.
