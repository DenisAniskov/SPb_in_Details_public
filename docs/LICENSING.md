# Лицензия на исходный код

**Решение не принято.** В репозитории намеренно нет файла `LICENSE`: выбор
лицензии на исходный код — решение автора проекта, а не следствие публикации.
Публичная доступность репозитория сама по себе **не** означает разрешения
свободно использовать, изменять или распространять код.

## Что от чего отделено

| Объект | Правовой режим |
| --- | --- |
| Исходный код приложения | Лицензия не выбрана; по умолчанию все права сохраняются за автором |
| Географические данные каталога, scenic-наборы, снимки дорожной сети | ODbL 1.0, © OpenStreetMap contributors (см. [`data/README.md`](../data/README.md)) |
| Редакционные тексты и подборки проекта | Авторские материалы; возможность переиспользования с базой описана в уведомлении каталога |
| Yandex MapKit и данные карты | Собственные условия Яндекса, не покрываются лицензией кода |
| Данные Open-Meteo/CAMS, ответы ИИ-модели | Собственные условия соответствующих сервисов |

Выбор лицензии на код не меняет и не отменяет обязательства ODbL по данным и
условия сторонних SDK.

## Рекомендация

Если приложение остаётся продуктом автора, а исходный код публикуется для
прозрачности, достаточно явно зафиксировать это:

- добавить файл `LICENSE` с текстом «All rights reserved» и кратким разрешением
  на чтение/сборку для личного ознакомления;
- добавить раздел в `README.md` со ссылкой на этот файл;
- сохранить уведомления ODbL и атрибуции сторонних сервисов (они уже есть).

Если цель — разрешить сообществу переиспользовать код, разумный вариант —
**MIT** для кода приложения: он совместим с открытыми зависимостями, прост и не
навязывает условий на данные. Для более явного патентного гранта подойдёт
**Apache-2.0**. В обоих случаях потребуется:

- добавить файл лицензии и указание авторства в `README.md`;
- продолжать распространять данные под ODbL и не перелицензировать
  редакционные тексты автоматически;
- не распространять вместе с кодом ключи, keystore и приватные конфигурации.

## Что нужно сделать перед объявлением лицензии

1. Выбрать режим: все права сохранены, MIT или Apache-2.0.
2. Добавить файл `LICENSE` (и `NOTICE`, если потребуется).
3. Указать лицензию и авторство в `README.md`.
4. Убедиться, что условия лицензии не конфликтуют с условиями распространения
   данных ODbL и сторонних SDK.
5. При смене режима в будущем — отметить, с какой ревизии действует новая
   лицензия.

До принятия решения не следует публиковать релизные артефакты как
«свободно используемые» и ссылаться на лицензию, которой в репозитории нет.
